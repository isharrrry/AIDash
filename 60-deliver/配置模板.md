# AIDash 配置模板（环境变量清单 + 占位符）

> **这份模板里没有任何真实令牌、密码、内网域名或 IP。**
> 示例列一律是占位符；表中“默认”列是代码里的公开默认值（`40-build/10-aidash/src/server/config.ts:61-89`），不是本机实际配置。
> 真正要填的值只放在**运行环境**里，不写进仓库、不写进脚本、不写进卡片或日志。

## 0. 快速启动

**依赖**：Node ≥ 24、pnpm 12.4.1；SQLite 由 `better-sqlite3` 内置，不需要单独安装数据库。

```bash
pnpm -C 40-build install     # 1) 安装依赖
pnpm -C 40-build build       # 2) 构建服务端
pnpm -C 40-build web:build   #    构建前端

# 3) 设置令牌（只从环境变量读，不要写进仓库或脚本）
set AIDASH_TOKEN=请换成一个足够长的随机串     # Windows 当前终端（不要带尖括号）
export AIDASH_TOKEN=请换成一个足够长的随机串  # macOS / Linux

# 4) 启动（任选其一）
pnpm -C 40-build start           # 等价于 node 40-build/10-aidash/dist/server/main.js
pnpm -C 40-build start:win       # Windows 推荐：先把 DB / 备份 / 静态目录钉成绝对路径并打印
```

打开 `http://127.0.0.1:8787/`，在登录页填入同一个令牌即可。

Windows 注意：`40-build/10-aidash/scripts/start-aidash.ps1` 必须保持 **UTF-8 with BOM**；没有 BOM 时 PowerShell 会按本地代码页解析，中文会乱码甚至报语法错误。`pnpm -C 40-build cli:build` 只构建已弃用的旧值守壳，新部署不需要。

## 1. 先记住四件事

1. **优先级（与设计文档相反，以实现为准）**：**凡是有页面设置（setting 表）的键，setting 最高** → 环境变量 → 配置文件 → 内置默认。代码是 `coalesce(persisted, config)`，persisted 在前（`settings-service.ts:256-282`）。`token`、端口、库路径这些没有 setting 的键才是「环境变量 > 配置文件 > 默认」。`config.ts` 头部注释已按实际实现改写；该优先级已按决策 A 收口（页面设置最高，03 §3.7.1 同步为四层），仍记为「新-5」以便追溯。
2. **AIDash 不会自动读 `.env`**：`config.ts:138-150` 只读 `process.env`，仓库也没有 dotenv 依赖。`.env` 只能当清单用，值必须通过系统环境变量或启动脚本注入。
3. **配置文件路径**：默认 `./aidash.config.json`（相对启动目录），可用 `AIDASH_CONFIG` 改。`40-build/00-platform/config/schema/aidash-config.schema.json` 是**运行时校验的事实源**：`config.ts` 的 `assertConfigFileShape()` 在启动时按它做键白名单，**拼错的键直接报 `CONFIG_UNKNOWN_KEYS` 并拒绝启动**，不再静默回退到默认值。该文件已加入 `.gitignore`。
4. **凭据只认环境变量**：`token`、`llm_api_key`、`llm.api_key` 出现在配置文件里会触发 `CONFIG_SECRET_IN_FILE` 并拒绝启动（已按 AGENTS §1 / REQ-FN-057 收紧）。LLM 密钥另一条合法来源是页面设置写入的加密文件（`~/.aidash/`）。本模板不给 `token` 字段。

## 6. 设置示例（全部是占位符）

**持久化到当前用户环境变量**（`setx` 写入用户注册表；设置后要重开终端才生效）：

```powershell
setx AIDASH_TOKEN "<在环境变量里设置>"
setx AIDASH_DB_PATH "<数据库绝对路径>"
setx AIDASH_BACKUP_DIR "<备份目录绝对路径>"
setx AIDASH_STATIC_DIR "<Web 静态产物绝对路径>"
setx AIDASH_LLM_ENDPOINT "<你的 OpenAI 兼容端点>"
setx AIDASH_LLM_MODEL "<你的模型名>"
```

> 只想当前会话生效时，用 PowerShell 的 `$env:` 语法设置同名变量；不要把值贴进任何会提交的文件。
> `setx` 的值有长度限制；令牌很长时优先用系统“环境变量”界面或启动器注入。

**部署脚本会钉死的四个变量**：`AIDASH_DB_PATH`、`AIDASH_BACKUP_DIR`、`AIDASH_STATIC_DIR`、`AIDASH_PORT`。用 `deploy.ps1` 时不要在外层再覆盖它们，否则脚本和实际运行会不一致。

## 7. 配置文件模板（JSON）

**不要把 `token` 写进这个文件**；让环境变量提供。下面的占位符是字符串，能被 JSON 解析，但不是可用的真实路径/端点，填入后才能部署。

```json
{
  "host": "127.0.0.1",
  "port": 8787,
  "db_path": "<数据库绝对路径>",
  "backup_dir": "<备份目录绝对路径>",
  "static_dir": "<Web 静态产物绝对路径>",
  "kb_root": null,
  "allow_empty_db": false,
  "log_level": "info",
  "llm": {
    "endpoint": "<你的 OpenAI 兼容端点>",
    "model": "<你的模型名>",
    "mode": "standard"
  }
}
```

说明：

- `host` 的 `127.0.0.1` 与 `port` 的 `8787` 是代码公开的默认值，不是本机实际配置；
- 键名必须和 `aidash-config.schema.json` 一致；拼错会启动失败；
- `llm` 嵌套写法与 `llm_endpoint` / `llm_model` 等扁平键等价，扁平键优先（`config.ts:180-198`）；
- **配置文件里不能写 `token`**：`config.ts` 启动时直接拒绝（`CONFIG_SECRET_IN_FILE`）。令牌只放 `AIDASH_TOKEN` 环境变量；设置页只保存 LLM API Key（加密落盘）。`.gitignore` 已覆盖 `.env`、`aidash.config.json`、`aidash-runner.json` / `aidash-watch.json`，但那只防误提交，不改变「写了就启动失败」。

## 8. 安全清单

- [ ] `AIDASH_TOKEN` 只在环境变量里，值不出现在仓库、脚本、卡片、日志、截图里；
- [ ] 旧配置仍用 `AIDASH_PASSPHRASE` 兼容时：≥8 字符，只放环境变量，确认局域网已有 TLS/反代；新配置直接用 `AIDASH_TOKEN`；
- [ ] `AIDASH_LLM_API_KEY` 优先用页面设置（加密落盘），其次环境变量；不写进配置文件；
- [ ] 备份 `~/.aidash/master.key`（或 `AIDASH_SECRET_DIR` 下的主密钥）：**它不在数据库备份里**，丢了旧密文永久解不开（`70-operate/已知坑清单.md:22`）；
- [ ] 主密钥与数据库备份**分开存放**，避免一次泄露同时拿到密文和钥匙；
- [ ] 配置里不写内网域名、内网 IP、带凭据的 URL；
- [ ] 跨主机部署（`AIDASH_HOST` 不是回环地址）必须先配 TLS/反向代理，并重新评估暴露面；
- [ ] 令牌疑似泄露时先轮换，再逐个更新 harness；轮换会让旧 harness 立刻 401（`30-design/设计文档包/06-安全性设计支撑材料.md:114-117`、`:217`）。轮换顺序：先验证新令牌可用，再失效旧令牌。

## 12. 数据、备份与恢复

| 内容 | 默认位置 | 说明 |
|---|---|---|
| 主数据库 | `40-build/10-aidash/data/aidash.db`（`AIDASH_DB_PATH`） | WAL 模式，伴生 `-wal` / `-shm` 两个文件 |
| 迁移前备份 | `40-build/10-aidash/backups/pre-migrate-<旧版本>-to-<新版本>-<时间戳>.db` | 每次升级 schema 前自动生成，文件名带版本，可据此反推迁移历史 |
| 手动备份 | `AIDASH_BACKUP_DIR`（默认 `40-build/10-aidash/backups/`） | 建议先停服，再连同 `-wal` / `-shm` 一起拷走 |

**空库防护**：启动时若配置的库文件不存在、但备份目录里已有 `*.db`，默认拒绝启动，日志写 `db_missing_with_backups`（错误码 `DB_MISSING_WITH_BACKUPS`）——十有八九是路径漂移，而不是真的“首次部署”。确认要新建空库时，显式设 `AIDASH_ALLOW_EMPTY_DB=true`。

**恢复步骤**：

1. 停服，避免 WAL 继续写入；
2. 用备份覆盖 `aidash.db`，同目录的 `-wal` / `-shm` 一并处理（按备份时点恢复或删掉旧文件）；
3. 启动，看 `/healthz` 返回的 `db_path` 是否指向预期文件；
4. schema 版本**不在** `/healthz` 返回体里（只有 `ok` / `status` / `version` / `db_path`），只能看启动日志、迁移前备份文件名或离线查询数据库。

**主密钥不在备份里**：`~/.aidash/master.key`（或 `AIDASH_SECRET_DIR` 下的主密钥）丢失后，旧密文永久解不开；备份策略见 §8 安全清单。

## 13. 知识库（OKF，只读）

`AIDASH_KB_ROOT` 指向一个 Markdown 目录：根目录含 `index.md`（`okf_version: "0.1"`），文章为 Markdown + YAML frontmatter。

- 服务只**读**该目录，不写、不改、不删；
- 索引落在 SQLite（`kb_doc` / `kb_fts`），换机器重新索引即可；
- `AIDASH_KB_ROOT` 未配置或路径无效时**不阻塞启动**，只把知识库状态显示为不可用；
- 检索用 SQLite FTS5 + 标签/类型过滤，不依赖向量库；
- 增量索引间隔由 `AIDASH_KB_INDEX_INTERVAL` 控制（默认 300 秒，范围 30~86400）。

## 14. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动即退出，日志 `CONFIG_MISSING` | 没设 `AIDASH_TOKEN` 环境变量 |
| 浏览器能开页面但 API 全 401 | 页面里填的令牌与进程环境变量不一致 |
| 启动报 `DB_MISSING_WITH_BACKUPS` | 库路径漂移；确认路径，或确认首次部署后显式 `AIDASH_ALLOW_EMPTY_DB=true` |
| 启动报 `CONFIG_UNKNOWN_KEYS` | 配置文件里有拼错或 schema 未收录的键；按 `aidash-config.schema.json` 核对 |
| 启动报 `CONFIG_SECRET_IN_FILE` | 配置文件里写了 `token` / `llm_api_key` / `llm.api_key`；改成环境变量或页面设置 |
| 通道一直显示“已停止” | 超过 `AIDASH_OFFLINE_THRESHOLD_SECONDS` 没有 MCP 调用；agent 发心跳或调工具即恢复 |
| 建议区一直“未生成” | 没配 LLM key，或 `AIDASH_ENRICHMENT_ENABLED=false`，或端点不可达 |
