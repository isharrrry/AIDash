# 故障记录模板

> **现在没有真实故障，所以这份文件只有模板、没有案例。** 编一个假故障跑 8A/8B，产出的是一份看起来很专业、实际没有证据的根因报告，比不写更糟。

## 0 填写纪律（先读这段）

1. **时间精确到分钟**，用同一个时区（默认本机 `Asia/Shanghai`）；
2. 每条结论后面标**证据等级**，没有证据的写「推测」；
3. **根因至少写两个候选**，各写「支持证据」和「怎么区分」；
4. 不知道就写「不知道 / 未验证」——空白比编造安全；
5. 记录里**不写令牌、密钥、内部账号明文**，只写「已脱敏」。

### 证据等级

| 等级 | 含义 | 例子 |
|---|---|---|
| **A** | 原始记录，可复核 | 日志原文、截图、`git show`、连续两次复现 |
| **B** | 可复核的操作记录 | 执行过的命令 + 时间 + 输出摘要 |
| **C** | 推断 | 「因为 X，所以大概是 Y」 |
| **D** | 口述/传闻 | 「有人说当时重启过」 |

| 字段 | 内容 |

## 2 影响面

- **谁受影响**：单用户 / 所有通道 / 仅某个通道
- **什么不可用**：卡片 / 任务树 / MCP 调用 / 页面 / 值守壳
- **数据是否受损**：未受损 / 可能丢失（范围）/ 已确认丢失（范围）
- **是否已扩散**：是（怎么扩散的）/ 否
