# 卡片正文表格与换行渲染修复（2026-11-06）

> 记录原则：只写真实执行过的命令与结果；失败也保留，不补“应该没问题”。
> 本轮只改 Web 端 Markdown 渲染与对应测试，不涉及数据库结构、服务端接口与部署进程。

## 1 现象与定位

卡片正文里的表格不渲染成表格，行也不换行——**没有换行、缺少表格**，读起来是一段带竖线的连续文字。

先确认是数据侧还是渲染侧：

| 检查项 | 结果 | 结论 |
|---|---|---|
| `detail_md` 里的换行数 | 118 个 | 存储完好 |
| 以 `\|` 开头的表格行 | 19 行，分隔行 `\| :-- \|` 齐全 | 存储完好 |
| 行尾是否混入 CRLF | 否 | 存储完好 |
| 旧渲染器对该文本的解析 | 表格块退化成 `kind: "paragraph"` | **渲染侧塌陷** |

根因两处，都在 `src/web/src/components/Markdown.tsx`：

1. **表格分隔行只认 3 个及以上短横线**（原正则 `-{3,}`）。harness 汇报实际写的是 `| :-- | :-- |`（每列 2 个），不匹配就把整张表当普通段落，竖线原样留在文字里，段落内换行又被 HTML 折叠 → 同时表现为“没有表格”和“没有换行”。
2. **行尾双空格没有按 GFM 处理成硬换行**。汇报开头的「日期 / 范围 / 基线」三行用行尾两个空格分行，未处理时被折叠成一行。

## 2 改动

| 文件 | 改动 |
|---|---|
| `40-build/10-aidash/src/web/src/components/Markdown.tsx` | 表格分隔行放宽为 `-+`（1 个及以上），并由另外三个条件防误判：上一行含竖线、必须有列分隔竖线、列数与表头一致 |
| 同上 | 行内渲染支持行尾 2 个及以上空格 → `<br>`；单换行仍按 GFM 折叠为空格 |
| `40-build/10-aidash/tests/markdown.test.ts` | 新增 2 条：`\| :-- \|` 与 `\|:-:\|` 两种分隔行都要解析成表格 |
| `40-build/10-aidash/tests/markdown-dom.test.ts` | 新建，4 条：硬换行生成 `<br>`、单换行不生成、三个空格不残留、表格渲染成真 `<table>` |
