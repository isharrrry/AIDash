# AIDash E2E（端到端 UI 回归）

**一条命令，起服务、起浏览器、造数据、跑完、全清。**

```bash
pnpm -C 40-build e2e
```

退出码 `0` = 全部通过，`1` = 有失败（含环境问题）。

---

## 1 这套东西解决什么问题

`tests/manual/` 里有 5 个手工脚本，但它们都有同一个毛病：**依赖外部已经启动的 8787 与 Edge 9222，还要人手传卡片 id**。也就是说，它们只能在「你刚好开着服务、刚好手上有两张待决策卡」的时候跑，跑完还会往真实库里写数据。

E2E 把这四件事自动化了：

| 手工脚本要人做的 | E2E 自动做的 |
|---|---|
| 先启动服务 | 自己起，端口动态分配，跑完杀进程 |
| 先启动 Edge 9222 | 自己起无头 Edge，独立 profile，跑完杀进程树 |
| 手工找两张待决策卡 | 通过 REST 造固定样例（通道 1 个、任务 1 个、卡片 2 张） |
| 跑在真实库上 | 跑在 `%TEMP%` 的一次性库上，跑完连目录删除 |

## 2 覆盖范围（6 条，实测全通过）

| # | 用例 | 断言什么 |
|---|---|---|
| 1 | 决策台 `#/` | 有「决策台」标题；待我拍板队列显示 question 卡；挂任务的 info 卡**不**混进决策队列 |
| 2 | 通道页 `#/c/<key>` | 标题用通道别名（不是 channel_key）；卡片流同时显示 info 与 question 两张卡 |
| 3 | 任务树 `#/tasks` | 本通道的任务标题出现在看板上 |
| 4 | 设置页 `#/settings` | 「设置与运维」「健康检查」「服务参数」三个区块都在 |
| 5 | 卡片抽屉 `#/?card=<id>` | 深链直接打开抽屉，标题与正文都渲染出来 |
| 6 | 鉴权（负向） | 清掉令牌后刷新 → 回到令牌输入页，且业务内容一个字都不出现 |

断言用的是**页面上可见的中文文本**，不是 CSS 选择器。这么做的理由：选择器绑定实现细节，改个 class 名就红一片；而「用户到底看见了什么」才是 UI 回归真正要守住的东西。代价是改文案也会让用例失败——但那恰好该被人看一眼。

## 3 不覆盖什么（说清楚，别误以为全覆盖）

| 没覆盖 | 为什么 |
|---|---|
| 移动端 / 窄屏布局 | 当前只有桌面单栏布局，没有独立断点需要守 |
| 拖拽移动任务、批量勾选、编辑器交互 | 需要更细的鼠标事件序列，价值低于维护成本；这部分靠 `tests/manual/` 的脚本随用随跑 |
| 视觉回归（像素比对） | 没有基线图库；像素比对在字体/缩放不同的机器上假阳性极高 |
| 性能 / 首屏耗时 | 无头模式的性能数字不能代表真实使用 |
| 并发（两个 harness 同时操作同一个任务） | 已在 `tests/http-routes.test.ts` 用 1×200 + 9×409 覆盖，属于接口层而非 UI 层 |

## 4 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node | ≥ 24 | 依赖全局 `WebSocket` 与 `fetch`，不引入第三方 CDP 客户端 |
| 构建产物 | `dist/server/main.js` + `dist/web/index.html` | 缺失时脚本会直接提示先跑 `pnpm -C 40-build build && pnpm -C 40-build web:build` |
| 浏览器 | Microsoft Edge | 默认查 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 与 `Program Files` 两处；换机器用 `AIDASH_EDGE_PATH` 指定 |
| 端口 | 任意空闲端口 | 服务端与 DevTools 各取一个，由内核分配，不与 8787/9222 冲突 |

### 可选环境变量

| 变量 | 作用 |
|---|---|
| `AIDASH_EDGE_PATH` | 指定 `msedge.exe` 绝对路径 |
| `AIDASH_E2E_KEEP=1` | 保留临时目录（库、浏览器 profile、密钥目录），排查失败时用 |
| `AIDASH_E2E_ALLOW_CONSOLE=1` | 不把页面控制台报错判为失败（默认严格） |

## 6 几个刻意的设计取舍

**为什么不用 Playwright / Puppeteer。**
技术规格清单 §6.4 已锁定「E2E 用 Edge 无头 + CDP」。引入 Playwright 会带进一份上百 MB 的浏览器和一条新的版本矩阵，与「单机自用、零第三方运行时依赖」的定位冲突。Node 24 自带 `WebSocket`，CDP 本身只是 JSON over WebSocket，四样本事（导航、求值、截图、收控制台错误）已经够用。

**为什么造数据走 REST 而不是直接插 SQLite。**
直接插库会绕过 service 层，造出来的数据可能违反业务不变量（任务缺事件行、卡片缺未读计数）。那样用例就跑在一个现实中不存在的状态上，通过也没有意义。

**为什么把控制台报错判为失败。**
页面可能「看起来渲染了」却在后台一直抛异常（比如某个轮询接口 500）。这类问题只有控制台能暴露，恰好是 UI 回归最容易漏的一类。临时排查时可以 `AIDASH_E2E_ALLOW_CONSOLE=1` 关掉。

**为什么清理必须杀进程树。**
Windows 上 Edge 会派生多个子进程，只 kill 父进程会留下僵尸占着 profile 目录，下次运行就删不掉临时目录。所以用的是 `taskkill /pid <pid> /T /F`。

**为什么跑完要显式 `process.exit()`。**
子进程即使都 kill 了，Node 也可能因为残留句柄迟迟不退出——表现是「用例都过了但命令不返回」。E2E 是一次性进程，跑完就退，不必等事件循环自然清空。

## 7 失败时怎么查

1. 看终端输出：失败用例会打印**当前页面可见文本的前 500 字**，通常一眼就能看出是「停在令牌页」还是「数据没渲染」。
2. 看截图：`50-verify/e2e/artifacts/<时间戳>/<用例名>.png`。
3. 要保留现场：`AIDASH_E2E_KEEP=1 pnpm -C 40-build e2e`，临时库与浏览器 profile 都会留在 `%TEMP%\aidash-e2e-*`。
