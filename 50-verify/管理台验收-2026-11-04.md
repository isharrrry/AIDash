## 6 过程问题与修正（验收脚本自身，不是产品缺陷）

| 次数 | 现象 | 原因 | 处理 |
|---|---|---|---|
| 第 1 次运行 | `POST /api/services/<id>/start` 返回 **415 CONTENT_TYPE_REQUIRED** | 验收脚本的写请求没有带 `application/json`；管理台按 Web 前端约定强制要求该头 | 修正脚本：所有 POST/PUT/PATCH 统一带 `content-type: application/json`（空体也带），与真实 Web 行为一致 |
| 第 2 次运行 | 退出测试阶段 `POST /start` 返回 **409 ALREADY_RUNNING** | 脚本在 runner 前置阶段已启动的临时 AIDash 仍在运行，退出测试又重复启动 | 修正脚本：退出测试复用现有运行态，只重启 runner |
| 第 3 次运行 | 全流程通过 | — | 31 项 PASS，`result: pass`，`error: null` |

> 415 与 409 都是管理台的**预期行为**（写接口必须 JSON；重复启动必须拒绝），不是缺陷。

## 7 遗留风险与未覆盖项

| # | 限制 / 未覆盖 | 影响 | 建议 |
|---|---|---|---|
| 1 | 本轮 UI 断言以 API + 单张总览截图为主，未逐页点击新建向导、配置页、日志页的交互控件 | 页面交互细节未在本轮回归；但管理台 Web 已由 42 条单元/集成测试覆盖鉴权、端口回退、配置校验等 | 后续补一条浏览器级 E2E（可复用 `50-verify/e2e` 的 Edge harness）覆盖向导/配置/日志页 |
| 2 | runner 只验证了启动、控制面就绪与停止；专用通道内没有任务，未触发 harness 真正执行任务 | `claude` 模板的 argv 拼装、任务文件/结果文件契约由管理台单测与 runner 自身测试覆盖，本轮未做真实任务闭环 | 需要时用一个低风险的测试任务做一次真实 harness 执行（会消耗模型额度） |
| 3 | 只验证了 Windows 路径：AIDash 停止走 `taskkill /T /F`，runner 控制面优先 | POSIX 的 SIGTERM/进程组路径未在本机验证 | 在 Linux/macOS 上跑一次同样的脚本或管理台单测的 POSIX 分支 |
| 4 | 只读登记 8787 时使用 `tokenSource: env` 且管理台进程没有 `AIDASH_TOKEN`，因此只验证了 health 探测与 `external` 状态；没有验证外部实例的令牌更新/打开网页 | 外部实例的令牌管理、`open` 跳转未覆盖 | 明确“只读登记”语义：要管理令牌请改用 manager 令牌源，或在页面补登记令牌 |
| 5 | 管理台退出测试用 SIGTERM 结束进程（Windows 上等价于关闭终端/结束进程）；未验证 Ctrl+C 在真实控制台里的键盘事件 | 行为与单测“模拟 Ctrl+C 退出”一致，但真实键盘路径未复现 | 可人工开一个终端按 Ctrl+C 观察一次（管理台已有单测覆盖） |
| 6 | 未验证 npm 打包（`npm pack` / GitHub Packages）与安装后运行 | 属于发布流程，不在本次验收范围 | 发布前单独跑 `npm pack --dry-run` 并校验包清单 |
| 7 | 管理台日志异常摘要是启发式的（结构化 `level` + 关键字兜底） | 可能漏报/误报；本轮 runner 无异常、AIDash 有 1 条启动告警 | 作为排查入口使用，不替代完整日志 |
| 8 | 临时 AIDash 是源码仓 `40-build/10-aidash/dist` 构建产物，不是部署副本 | 验证的是源码构建产物；部署副本 `D:\app\AIDash\server\dist` 未参与管理台启停 | 若要把管理台用于部署副本，登记时把工作目录/入口指向部署目录即可（本轮已只读验证 8787） |

## 8 复跑方式

本轮验收使用一次性脚本（位于系统临时目录，验收后已删除，不随仓库发布）。要复跑，按以下顺序：

```bash
# 1) 质量门禁
pnpm -C 40-build typecheck
pnpm -C 40-build manager:test
pnpm -C 40-build manager:build

# 2) 临时管理台（不要用默认 ~/.aidash/manager）
export AIDASH_MANAGER_HOME="$(mktemp -d)/manager-home"
node 40-build/30-aidash-manager/bin/aidash-manager.mjs web --port 4289 --no-open

# 3) 另开终端：用启动时打印的带 token 链接打开页面，按本文第 4 节顺序操作
#    新建 AIDash（18887、临时库）→ 启动 → /healthz → 停止
#    登记 8787（只读）→ 新建 runner（claude 模板、专用通道）→ 启动 → 停止
#    查看日志与异常摘要 → 停止管理台并确认服务仍在 → 清理临时服务与目录
```

关键约束：临时端口 4289/18887、临时 SQLite 库、专用通道、临时 `AIDASH_MANAGER_HOME`；不要指向 `~/.aidash/manager`、`D:\app\AIDash\data\aidash.db` 或现有 runner 的 data_dir。
