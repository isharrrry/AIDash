# MOD-006 知识库索引 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/services/kb-service.ts` | 遍历、frontmatter 解析、增量判定、检索、路径安全 |
| `src/server/repos/support-repos.ts` | `KbRepo`：文章表与 FTS5 的读写 |
| `src/server/workers/background.ts` | 按 `kb_index_interval_seconds`（默认 300 秒）触发增量索引 |
| `src/server/services/settings-service.ts` | 运行时改 `kb_root`（getter 传入，改完不必重启） |

## 2 线程与并发

- 索引在请求线程之外由后台 worker 跑，单次串行；同一文件按内容 `sha256` 判断变没变；
- 索引与检索共用一条 SQLite 连接，写索引会短暂占用写锁；
- 检索是纯读，多词查询走 FTS `MATCH`，不是整串 `LIKE`。

## 3 错误分支

| 触发 | 出口 |
|---|---|
| `kb_root` 没配 | `isConfigured()` 为假；增强与检索都返回空，不报错 |
| 请求的 `path` 归一化后越出 `kbRoot` | 拒绝，按参数非法处理 |
| 单文件超 2 MB / 超过 5,000 个文件 | 跳过，记进 `errors`，不中断整轮索引 |
| frontmatter 缺失或 YAML 坏 | 该文件跳过并计数，其余照常索引 |
| FTS 查询语法错 | 退化为 `LIKE` 子串检索，但**不是静默的**：服务层在响应里带 `degraded: true` 与 `degraded_reason: "FTS_QUERY_FAILED"`，服务端同时 `warn` 记录真实错误，前端在搜索框下明确提示「检索已降级」。退化的结果可用，但调用方看得出这次不是 FTS |

## 5 边界

不在本模块做的事：不写用户目录、不做向量检索、不解析 Markdown 之外的格式。
