# MOD-005 增强服务 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/services/enrichment-service.ts` | 队列、KB 检索、提示词选择、输出收敛、落 `unavailable` |
| `src/server/services/llm-service.ts` | 唯一的 OpenAI 兼容客户端：超时、鉴权、错误码、响应解析 |
| `src/server/services/secret-store.ts` | 页面写入的密钥加解密（AES-256-GCM） |
| `src/server/services/settings-service.ts` | 端点/模型/模式/提示词的运行时读写 |
| `src/server/services/memory-digest-service.ts` | 按项目归纳记忆（同一 LLM 客户端，独立调度） |
| `src/server/services/assistant-memory-learner.ts` | AIDash 自身记忆的学习与注入 |
| `tests/fakes/fake-llm.ts` | 假 LLM 网关：可造 429 / 坏 JSON / 空 choices / 挂死 / 断连 |

## 2 线程与并发

- 队列在进程内，**串行执行（并发 1）**；`drain` 保证同一时刻只有一个 `runOne`；
- `pending` 状态持久化在库里，重启后由后台 worker 扫回来，不丢任务；
- LLM 调用是 `await fetch`，超时由 `AbortSignal.timeout` 控制，用户取消再叠加一个 signal。

## 3 错误分支

| 触发 | 卡片上的 `reason` | 备注 |
|---|---|---|
| 增强开关关闭 | `enrichment_disabled` | 状态 `skipped`，不发请求 |
| 端点/模型/密钥缺一 | `llm_not_configured` | 状态 `unavailable`，不发请求 |
| 上游超时 | `LLM_TIMEOUT` | 带 `elapsed_ms`，不带上游响应体 |
| 非 2xx | `LLM_HTTP_ERROR` | 只记状态码；上游回显的密钥绝不落库 |
| 响应不是 JSON / `choices` 为空 | `LLM_INVALID_RESPONSE` / `LLM_EMPTY_RESPONSE` | 两者分开，排查方向不同 |
| 模型输出不是可解析的增强 JSON | `LLM_OUTPUT_NOT_JSON` | 不存半截 JSON |
| 用户取消 | `LLM_CANCELLED` | 与超时分开，避免误判成模型慢 |

## 5 边界

不在本模块做的事：不做建议自动采纳、不读取或转述用户密钥、不把模型输出当指令执行。
