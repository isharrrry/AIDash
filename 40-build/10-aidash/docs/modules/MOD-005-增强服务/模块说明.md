# MOD-005 增强服务 · 模块说明

> 本目录只放交底文字，代码不在这里。源码位置见同目录《实现约定》§1。

## 职责

用外部 LLM 给卡片补「分析 + 建议 + 知识库依据」。三条硬底线：

1. **可选**：没配密钥或关掉开关，直接 `skipped`/`unavailable`，卡片照常可用；
2. **不污染**：任何失败都不改卡片正文，只在增强字段里记一个可读原因；
3. **不自动落地**：建议永远停在展示层，采纳是用户在页面上的显式动作（REQ-FN-038）。

## 已知偏差

| # | 设计怎么说 | 实际怎么做 | 影响 |
|---|---|---|---|
| 1 | §3.5.1「每卡最多重试 3 次，1s/4s/16s 指数退避」 | 后台每 60 秒扫一次 `pending` 重新入队，**没有次数上限、没有指数退避** | 持续失败会每分钟重试一次，费用与日志会累积 |
| 2 | §3.5.2 写死 `timeoutMs: 5_000, maxTokens: 800` | 用统一设置 `llm_timeout_ms`（默认 60 秒）与档位预算（max 8192） | 单次更贵；换来与「测试连接」共用一条参数路径 |
| 3 | §3.5.3「解析失败 → 用模板建议（建议人工复核）」 | 解析失败直接标 `unavailable`，不给模板建议 | 页面显示「增强不可用」而不是兜底建议；属未落地项 |
| 4 | §3.5.1 状态四态 `pending/running/done/unavailable` | 多一个 `skipped`（开关关闭或未配置） | 前端需识别第五态；已处理 |
| 5 | §3.5 只覆盖卡片增强 | 记忆归纳、助手记忆学习器也走同一个 `LlmService`，但不在增强队列内 | 契约散在 AGENTS 4.3；改 LLM 客户端会同时影响三条链路 |
