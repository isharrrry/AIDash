# MOD-009 值守壳 CLI · 模块说明

> 本目录只放交底文字，代码不在这里。源码位置见同目录《实现约定》§1。

## 职责

常驻命令行的「值守人」：轮询 `pending` 任务 → 认领 → 起本地 agent 命令干活 → 续租、回报、退出。

三条边界：

- **纯 MCP 客户端**：只走 `tools/call`，不依赖 REST；
- **令牌只从环境变量读**：配置文件里没有令牌项，也不许写进去；
- **日志脱敏**：子进程输出里出现 `AIDASH_TOKEN=...` 一律抹成 `***`。

## 已知偏差

| # | 设计怎么说 | 实际怎么做 | 影响 |
|---|---|---|---|
| 1 | §3.9.1 `harness.command` 单命令 + 顶层 `tags` | `commands[]` 规则数组：每项 `command` + `tags`/`title_prefix`/`channel_key`，或显式 `match_all:true` | 一个壳可同时跑多种活；但对老配置，`harness`、顶层 `tags` 只打告警、不生效 |
| 2 | 无 `gap_seconds` | 新增 `gap_seconds`（两条命令之间的最小间隔，0~3600） | 防止连发命令把机器打满；设计未写 |
| 3 | 配置里有 `token_env` | 字段保留但**忽略**，只告警「令牌只从 `AIDASH_TOKEN` 读」 | 老配置不会因为换了变量名就偷偷生效 |
| 4 | §3.9.3 进程树终止 | Windows 用 `taskkill /PID <pid> /T /F`；POSIX 用 `detached` 建进程组后 `SIGTERM` → 宽限 → `SIGKILL` | 与设计一致；额外处理了「kill 也没触发 close」的兜底 |
