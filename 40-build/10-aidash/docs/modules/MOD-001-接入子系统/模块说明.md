# MOD-001 接入子系统 · 模块说明

> 本目录只放交底文字，代码不在这里。源码位置见同目录《实现约定》§1。

## 职责

收 HTTP 与 MCP 两种入口，做四件事：**认证、限流、参数校验、错误收敛**。
它不含业务规则——业务判断在各 service 里，这里只负责「把请求安全地送进去，把结果统一地送出来」。

有界等待（`card.ask` / `card.wait`）的**配额与上限**也归这里，因为它是进程级资源，不属于单张卡。

## 构建命令

```bash
pnpm -C 40-build typecheck          # 含本模块的静态检查
pnpm -C 40-build test http-routes   # 单模块用例
pnpm -C 40-build build              # 编译到 dist/server
```

## 已知偏差

| # | 设计怎么说 | 实际怎么做 | 影响 |
|---|---|---|---|
| 1 | §3.1.2 写多令牌 `tokens[]` + `scopes:['read','write']` | 只有一个 `AIDASH_TOKEN`；`Ctx.isOwner` 恒为 `true` | 单用户场景够用；将来要多角色必须改这里 |
| 2 | §3.1.1 只画了 `rateLimit()` 与 `429 + Retry-After` | 内存令牌桶，按分钟窗口，进程重启清零 | 多实例部署时各算各的；当前单机不受影响 |
| 3 | 未规定 MCP 与 REST 的等待上限差异 | MCP 侧 25 秒（`AIDASH_MCP_WAIT_CAP_SECONDS`），REST 侧 300 秒 | 故意的：不等 MCP 客户端先判超时，见 AGENTS 4.2 |
