# MOD-002 通道与卡片服务 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/services/card-service.ts` | 发卡、回答、批量回答、过期、列表、已读；按 type 分支赋字段 |
| `src/server/services/channel-service.ts` | upsert、归档恢复、别名、workdir、统计与在线判定 |
| `src/server/services/state-machine.ts` | **任务**状态机 SM-001（转移表、认领令牌、取消守卫）；卡片与通道没有独立状态机，守卫在 `card-service.ts` / `channel-service.ts` 里按 type 分支 |
| `src/server/repos/card-repo.ts` | `card` / `card_event` / `card_read` 的 SQL |
| `src/server/repos/channel-repo.ts` | `channel` 的 SQL 与按 project 分组查询 |

## 2 线程与并发

- 发卡：一个事务里写卡 + 事件 + 审计；任何一步失败整体回滚。
- 增强调度：走 `setTimeout(0)` 排到事务**之外**，避免「库还没提交就去读卡」。
- 已读标记：`card_read` 用唯一键 `(card_id, actor_label)` 幂等，重复标记不改时间。

## 3 错误分支

| 触发 | 出口 |
|---|---|
| 非 question 卡缺 `task_id` | `INVALID_ARGUMENT / TASK_REQUIRED` |
| question 卡缺四段之一 | `INVALID_ARGUMENT`，`details` 指出缺哪段 |
| 选项 id 重复 / 找不到 | `INVALID_ARGUMENT / OPTION_NOT_FOUND` |
| 不允许自由文本却传了 | `INVALID_ARGUMENT / FREE_TEXT_NOT_ALLOWED` |
| 已作答 / 已归档 | `CONFLICT / CARD_NOT_OPEN`、`CARD_ARCHIVED` |
| 命中令牌/密码/私钥模式 | `INVALID_ARGUMENT`，只回模式名，不回显原文 |
