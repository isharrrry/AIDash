# MOD-003 任务树服务 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/services/task-service.ts` | 全部状态事件、认领、租约、移动/复制、暂缓、隐患、结束通知 |
| `src/server/services/state-machine.ts` | SM-001 转移表与守卫（哪些事件在哪些状态合法） |
| `src/server/repos/task-repo.ts` | 物化路径读写、子树前缀改写、列表/树查询、`include_closed` 过滤 |
| `src/server/repos/support-repos.ts` | `task_event`、`harness`、`audit` 的事件与心跳读写 |

## 2 线程与并发

- 认领：`UPDATE ... WHERE status='pending'` 加受影响行数判断，靠 SQLite 的写锁保证原子；
- 租约：`claim_expires_at` 由 `claim_token` 对应的 harness 续期；后台 worker 每拍调 `expireLeases`；
- 移动/复制：`txImmediate` 事务内先改自己再批量改子树，避免中途被读到半个树。

## 3 错误分支

| 触发 | 出口 |
|---|---|
| 认领已被别人拿走 | `ALREADY_CLAIMED`（可重试，换任务） |
| 令牌与当前认领方不符 | `CLAIM_TOKEN_MISMATCH` |
| 状态不允许该事件 | `CONFLICT / TASK_STATE_INVALID` |
| 完成但缺证据卡 | `EVIDENCE_REQUIRED`；证据卡不存在/不属于本任务 → `EVIDENCE_INVALID` |
| 移动成环 / 超最大深度 | `TASK_CYCLE` / `TASK_DEPTH_EXCEEDED` |
| 暂缓/隐患事件用在错的对象上 | `TASK_NOT_DEFERRED` / `TASK_RISK_NOT_FLAGGED` / `TASK_RISK_ALREADY_RESOLVED` |
| 需要原因却没给 | `REASON_REQUIRED` |
