# MOD-007 审计与配置 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/config.ts` | 分层配置合并、默认值、config 文件读取 |
| `src/server/startup.ts` | 路径解析成绝对路径、空库误连检查 |
| `src/server/services/settings-service.ts` | 运行时设置（`setting` 表 `runtime` 键）、五类提示词、能力就绪判定 |
| `src/server/services/secret-store.ts` | 密钥加解密与主密钥管理 |
| `src/server/services/audit-service.ts` | 审计写入（与业务同事务） |
| `src/server/db/migrate.ts` + `src/server/main.ts` | 迁移执行与迁移前备份 |
| `src/server/http/routes/admin.ts` | 健康、备份、审计、设置的 REST |
| `40-build/00-platform/config/schema/aidash-config.schema.json` | 配置文件 Schema（`additionalProperties:false`） |

## 2 线程与并发

- 配置在启动时解析并冻结；运行时设置每次从 `setting` 表读，改完即时生效；
- 审计与业务写在同一事务里，业务回滚审计也回滚；
- 迁移是「备份文件 → 单事务执行 → 写版本号」，失败按备份恢复；
- 后台 worker 按保留期清理卡片/日志。审计保留期除了 30~3650 的范围校验，还有**只能调长**的守卫：小于当前值直接拒绝（`AUDIT_RETENTION_CANNOT_SHRINK`，`details` 带 `current` / `requested`），相等视为幂等放行。范围校验挡不住「把 730 改成 30」这种一次销毁两年证据的操作，所以必须有这一层。

## 3 错误分支

| 触发 | 出口 |
|---|---|
| 缺 `AIDASH_TOKEN` | 启动失败，打印缺哪一项（不打印其它配置值） |
| 库文件不存在但备份目录有 `*.db` | 默认拒绝启动；`AIDASH_ALLOW_EMPTY_DB=true` 才建空库 |
| 迁移中途失败 | 用迁移前备份恢复，然后抛错退出 |
| 配置文件里有未知键 | 启动失败，报 `CONFIG_UNKNOWN_KEYS`（`details` 列出未知键，不打印值）。`config.ts` 的 `assertConfigFileShape()` 把 Schema 的 `additionalProperties:false` 真正接进了运行时；顶层与 `llm` 嵌套层都查 |
| 配置文件里有 token / llm_api_key / llm.api_key | 启动失败，报 `CONFIG_SECRET_IN_FILE`，提示改用对应环境变量。凭据只有环境变量（或页面写入的加密文件）两条路 |
| 主密钥缺失/损坏 | **不自动重建**：有旧密文但主密钥缺失/损坏时，`SecretStore` 返回 `unreadable` + 原因（`master_key_missing` / `master_key_invalid` / `decrypt_failed` / `secrets_file_invalid`），写入新密钥会抛 `SECRET_MASTER_KEY_MISSING`；启动时打 `secret_store_unreadable` WARN，设置页显示 `key_state` / `key_error` 并提示重设。只有「没有任何旧密文」时才允许新建主密钥 |
