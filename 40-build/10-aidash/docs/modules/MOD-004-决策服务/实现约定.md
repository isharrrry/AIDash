# MOD-004 决策服务 · 实现约定

> 本文件只写「怎么落地」。与设计冲突时以设计为准，冲突记在《模块说明》的「已知偏差」。

## 1 单元划分

| 文件 | 职责 |
|---|---|
| `src/server/services/decision-service.ts` | 等待注册表：`wait` / `resolve` / `cancelAll` / `size`，以及决策编排 |
| `src/server/services/card-service.ts` | 答案落库、批量回答、问题过期（`expireDueQuestions`） |
| `src/server/mcp/wait-cap.ts` | 把调用方要的等待秒数压到 `mcp_wait_cap_seconds` |
| `src/server/workers/background.ts` | 定时扫到期问题并标记 `expired` |

## 2 线程与并发

- 每个等待者是一个 Promise；答案到达时由 `resolve(cardId, answer)` 唤醒；
- 全局等待数受 `max_waiting_requests` 限制，超限直接 `BUSY`，不排队；
- 关服务时 `cancelAll()` 先释放所有等待者，否则 HTTP `close()` 会等到超时。

## 3 错误分支

| 触发 | 出口 |
|---|---|
| 对非 question 卡回答 | `CONFLICT / CARD_NOT_QUESTION` |
| 重复回答 | `CONFLICT / CARD_NOT_OPEN` |
| 选项不存在 | `INVALID_ARGUMENT / OPTION_NOT_FOUND` |
| 不允许自由文本却传了文本 | `INVALID_ARGUMENT / FREE_TEXT_NOT_ALLOWED` |
| 等不到答案 | 不是错误：MCP 返回 `{status:'pending', card_id}`，REST 到点返回空答案 |
| 等待配额满 | `BUSY`（可重试） |
