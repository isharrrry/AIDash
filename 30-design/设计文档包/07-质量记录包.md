## 0 使用纪律

本文件是质量记录，一旦写错，会让后来的人误以为某项质量活动已经发生。因此：

1. **状态只用 5 个值**：`待发生` / `已发生-通过` / `已发生-不通过` / `不适用` / `已关闭`。
   不写“基本通过”“差不多”“遗留小问题”这类模糊词——模糊状态等于没有状态。
2. **未发生的事不编记录号**。空表比假记录安全：空表说明还没做，假记录会让后来的人跳过检查。
3. **每个「已发生-」必须有三件证据**：命令或依据、输出（摘要或文件路径）、日期。
   没有证据的「已发生-通过」等于没有通过。
4. **本文件不定义编号空间**。文中出现的 `GAP-*`、`SCR-*`、`SAFE-*` 均为引用，
   定义方分别是 [界面设计说明.md](./界面设计说明.md) 与 [06-安全性设计支撑材料.md](./06-安全性设计支撑材料.md)。
5. **更改记录不等于批准记录**。文档已改动 ≠ 更改已获批；批准未发生就如实写 `待发生`。
6. **开源发布后的例外**：项目开发期存在逐轮内部研发台账（本轮的命令输出、任务编号、浏览器断言明细）。
   这些明细不随开源仓库发布，本文件中以“摘要”标注的结论只能视为历史陈述，**不能作为独立复核依据**；
   能被复现的只有 §2.1 的三个脚本与 `pnpm test`。

### 2.3 迭代期验证汇总（摘要）

开发过程中每一轮界面或数据模型改动都按同一节奏验证：`pnpm typecheck` → `pnpm test` → `pnpm build` → `pnpm web:build`
→ 停服备份（`db + wal + shm`）→ 应用迁移 → 重启 → REST/MCP 探针 → 无头浏览器 CDP 断言（每轮 6~19 项）。

到 V2.0 定稿时：**27 个测试文件 / 230 个用例全部通过**，语句覆盖率 82.8%；
每轮迁移后都核对了 `schema_version` 与历史数据条数，未出现数据丢失。
逐轮记录号与断言明细同 §2.2，属于内部台账，不随仓库发布。
