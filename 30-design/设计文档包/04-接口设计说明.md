## 1. 通用约定

### 1.1 传输与编码

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1 或 HTTP/2 |
| 编码 | UTF-8；请求/响应 `application/json`（MCP 遵循 Streamable HTTP 规范） |
| 地址 | 默认 `http://127.0.0.1:8787` |
| 路径前缀 | REST：`/api`；MCP：`/mcp` |
| 最大请求体 | 10 MB（任务描述允许内嵌 base64 截图；按字符上限 2,000,000 校验，UTF-8 最坏约 8 MB） |

### 1.2 认证

```
Authorization: Bearer <AIDASH_TOKEN>
```

- 单一令牌；可用 `token_label` 区分来源（如 `claude-dev`、`watchdog-a`）。
- 缺失或错误 → `401 UNAUTHORIZED`。
- **鉴权范围**：只罩住 `/api/*` 与 `/mcp`。静态页面、`/assets/*` 与 `/healthz` 免鉴权——
  浏览器导航和 `<script>` 请求不会携带 `Authorization`，全局鉴权会让页面在输入令牌前就 401，
  SPA 永远打不开；静态产物不含业务数据，数据边界仍在 `/api` 与 `/mcp`。
- 令牌不得出现在 URL 查询参数中（避免日志泄露）。

### 1.3 响应包络

**REST 成功**：

```json
{
  "schema_version": "1.0",
  "data": { },
  "meta": { "request_id": "req_01J..." }
}
```

**REST 分页**：

```json
{
  "schema_version": "1.0",
  "data": [],
  "meta": { "page": 1, "page_size": 50, "total": 123, "has_more": true }
}
```

**REST 错误**：

```json
{
  "schema_version": "1.0",
  "error": {
    "code": "CONFLICT",
    "message": "ILLEGAL_TRANSITION:done->start",
    "retryable": false,
    "details": { "from": "done", "event": "start", "allowed_events": [] }
  },
  "meta": { "request_id": "req_01J..." }
}
```

**MCP 工具结果**：`structuredContent` 为 `{ "schema_version": "1.0", ...payload }`；错误使用 JSON-RPC error（`code` 映射见 §2.3）。

### 1.4 幂等

- 写工具/写接口接受 `idempotency_key`（字符串，≤128）。
- 相同 key 的重复请求返回同一资源，不产生第二条事件。
- 作用域：卡片为“同通道内”；任务为“全库”。
- 未提供 key 时正常执行，但 MCP 响应带 `idempotency_hint`。

### 1.5 分页与排序

| 参数 | 默认 | 上限 |
|---|---|---|
| `page` | 1 | — |
| `page_size` | 50 | 200 |
| `sort` | `created_at:desc` | 枚举：`created_at`/`updated_at`/`priority`/`due_at` |
| `order` | `desc` | `asc`/`desc` |

### 1.6 时间

- 对外一律 ISO 8601 带时区：`2026-10-23T08:00:00.000Z`。
- 存储为整数毫秒（见 03 §2.4）。
- 所有“过期/租约”判断以服务端时间为准。

### 1.7 版本

- 每个响应带 `schema_version`（当前 `1.0`）。
- 只做加法兼容；破坏性变更升主版本并在 `/mcp` 初始化响应声明。
- `AGENTS.md` 另带 `contract_version`，与 `schema_version` 独立演进。

## 2. 错误码

### 2.1 错误码表

| code | HTTP | retryable | 含义 | 调用方应做什么 |
|---|---|---|---|---|
| `INVALID_ARGUMENT` | 400 | false | 参数缺失/格式错误/枚举非法 | 修正参数 |
| `UNAUTHORIZED` | 401 | false | 令牌缺失或错误 | 检查令牌 |
| `FORBIDDEN` | 403 | false | 无权限（如非 owner 移动任务） | 换操作主体 |
| `NOT_FOUND` | 404 | false | 资源不存在 | 检查 ID |
| `CONFLICT` | 409 | false | 状态冲突/非法转移/环 | 读最新状态后重试 |
| `ALREADY_CLAIMED` | 409 | true | 任务已被他人认领 | 稍后重试或跳过 |
| `EVIDENCE_REQUIRED` | 409 | false | 完成缺证据 | 先发状态/产物卡 |
| `RATE_LIMITED` | 429 | true | 超过速率限制 | 按 `Retry-After` 等待 |
| `BUSY` | 503 | true | 等待配额满/数据库忙 | 退避后重试 |
| `INTERNAL` | 500 | false | 未预期错误 | 上报，不盲目重试 |

### 2.2 错误详情约定

- `details` 只放**可公开**的元数据；不含 SQL、堆栈、文件路径、令牌。
- 守卫失败时 `details.guard` 给出守卫 ID（如 `G-T14`），便于对照 03 §4.3。

### 2.3 MCP 错误映射

| 业务 code | JSON-RPC code |
|---|---|
| `INVALID_ARGUMENT` | `-32602` |
| `NOT_FOUND` | `-32004` |
| `UNAUTHORIZED` | `-32001` |
| `FORBIDDEN` | `-32003` |
| 其他业务错误 | `-32000`（`data.code` 保留业务码） |

### 3.2 卡片对象（对外形状）

```json
{
  "id": "cd_01JABC",
  "channel_id": "ch_01JABC",
  "channel_key": "devhost/myproj/auth-bug",
  "type": "question",
  "status": "open",
  "priority": "P1",
  "title": "登录失败时是否自动登出？",
  "background_md": "议题背景：……",
  "goal_md": "达到目的：……",
  "research_md": "调查参考：……",
  "decision_md": "决策项：……",
  "options": [
    {
      "id": "1",
      "label": "自动登出",
      "description": "…",
      "pros_md": "- 安全边界清晰",
      "cons_md": "- 可能打断正在填写的表单",
      "recommendation_role": "primary"
    },
    {
      "id": "2",
      "label": "仅提示",
      "description": "…",
      "pros_md": "- 不打断操作",
      "cons_md": "- 用户可能忽略风险",
      "recommendation_role": "backup"
    }
  ],
  "allow_free_text": false,
  "default_action": null,
  "due_at": "2026-10-24T08:00:00.000Z",
  "answer": null,
  "task_id": "tk_01JABC",
  "read_at": null,
  "enrichment": {
    "status": "done",
    "analysis_md": "……",
    "suggestions": [{ "text": "…", "rationale": "…", "confidence": 0.72 }],
    "kb_refs": [{ "path": "Wiki/工程/登录.md", "title": "登录设计", "excerpt": "…" }],
    "model": "…",
    "has_kb_basis": true
  },
  "created_at": "2026-10-23T08:00:00.000Z",
  "updated_at": "2026-10-23T08:00:00.000Z"
}
```

**各类型差异字段**：

| type | 必填字段 | 可选字段 |
|---|---|---|
| `info` | `title`, `body_md`, `severity`, `task_id` | `links[]` |
| `handoff` | `recipient`, `channel_kind`, `reason`, `message_md`, `task_id` | `due_at`, `handoff_state` |
| `question` | `title`, `background_md`, `goal_md`, `research_md`, `decision_md`, `options[2~10]` | `allow_free_text`, `default_action`, `due_at`, `task_id`, `blocking` |
| `suggestion` | `analysis_md`, `suggestions[≥1]`, `task_id` | `kb_refs[]`, `confidence` |
| `status` | `summary`, `result`, `task_id` | `detail_md` |
| `artifact` | `url`, `kind`, `summary`, `task_id` | `size_bytes` |

**归属与已读规则（4.0 起）**：

- 非 `question` 卡缺 `task_id` → `VALIDATION_FAILED`（REST）/ `INVALID_ARGUMENT`（MCP），不落库；`question` 允许为空。
- `read_at` 是卡片已读时间；`null` 表示未读。已读是单用户全局状态，换浏览器一致。
- `POST /api/cards/{id}/read` 幂等：重复调用保留第一次的 `read_at`，不会刷新成最后一次。
- 归档不算已读，但归档卡不再计入未读数，否则红点永远清不掉。

**`question.options[]` 的字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string(≤64) | 是 | 卡内唯一 |
| `label` | string(≤200) | 是 | 选项名称 |
| `description` | string(≤4000) | 否 | 一句话说明 |
| `pros_md` | string(≤4000) | 是 | 优点（Markdown） |
| `cons_md` | string(≤4000) | 是 | 缺点/代价（Markdown）；没有明显缺点写“无明显缺点” |
| `recommendation_role` | `primary` \| `backup` | 是 | 恰好 1 个 `primary` + 1 个 `backup` |
| `recommendation` | string \| boolean | 否 | 旧字段，仅为兼容历史数据保留，不作为主/备推荐的唯一依据 |

> `status.result` 只接受 `success`/`failed`/`blocked`/`partial`；入口会把历史 `ok`/`fail` 归一化，
> 数据库只存这 4 个值。`suggestion.analysis_md` 落 `body_md`，`suggestions`/`kb_refs`/`confidence`
> 落独立列；`question.blocking` 缺省 false，`default_action` 只记录、不自动执行。
>
> **兼容性**：历史 `question` 卡可能没有 `goal_md`/`research_md`/`decision_md` 或选项的 `pros_md`/`cons_md`/`recommendation_role`，
> 查询返回 `null`，界面显示“未提供”；**新建** `question` 卡（`card.post` 或 `card.ask`）必须完整，
> 否则 `INVALID_ARGUMENT`。

  "title": "认证 500 排查",
  "project": "myproj",

```

| 字段 | 说明 |
|---|---|
| `project` / `topic` | 主对话 / 子对话；Web 显示为 `project / topic` |
| `workdir` | 通道对应的项目根目录，≤500 字符，可为 `null` |
| `task_count` | 通道内全部任务数（含终态） |

| `agent_online` | `last_mcp_at` 距今 ≤ `AIDASH_OFFLINE_THRESHOLD_SECONDS`（默认 180 秒）；与任务数、心跳无关 |

`POST /api/channels` 请求体为 `{channel_key, title?, workdir?}`；`workdir` 只在非空时登记/更正，不传不会清空已有值。

  "claimed_at": "2026-10-24T08:00:00.000Z",

  "completed_at": null,
  "failed_at": null,
  "cancelled_at": null,
  "blocked_reason": null,
  "fail_reason": null,
  "cancel_reason": null,
  "defer_reason": null,
  "deferred_at": null,
  "deferred_until": null,
  "risk_note": null,
  "risk_flagged_at": null,
  "risk_resolved_at": null,
  "risk_resolution": null,

  "created_at": "2026-10-23T08:00:00.000Z",
  "updated_at": "2026-10-24T08:01:00.000Z"

```

> `claim_token` **不出现在查询结果中**，只在 `claim` 响应里返回一次，避免被日志或前端泄露。

> `category` 是**单值**分类（≤40 字符，空白归一为 `null`），与多值 `tags` 分工不同：`tags` 用于跨任务检索，`category` 用于任务树的一列展示（如“功能/缺陷/维护”）。任务树没有分类时显示 `—`。

**`description_md` 的体积策略**：描述上限 2,000,000 字符，允许正文内嵌 base64 截图。为避免任务树和列表每分钟轮询时把截图全文搬来搬去，`GET /api/tasks`、`GET /api/tasks/tree` 与 MCP `task.list` / `task.tree` 默认返回 `description_md: null`；需要正文时显式传 `include_description=true`。`GET /api/tasks/{id}`、创建与更新任务的响应始终返回完整正文，前端详情直接使用它。

**任务时间线字段**（`TaskView`，所有任务查询/状态事件返回）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `claimed_at` | ISO \| null | 最近一次认领时间；`claim`（含过期租约接管）写入，续租不改写 |
| `started_at` | ISO \| null | 开始执行时间；`start` 写入 |
| `blocked_at` | ISO \| null | 最近一次阻塞时间；`block` 写入 |
| `completed_at` | ISO \| null | 完成时间；`complete` 写入 |
| `failed_at` | ISO \| null | 失败时间；`fail` 写入 |
| `cancelled_at` | ISO \| null | 取消时间；`cancel` 写入 |
| `blocked_reason` | string \| null | 阻塞原因；取 `block` 的 `reason` |
| `fail_reason` | string \| null | 失败原因；取 `fail` 的 `reason` |
| `cancel_reason` | string \| null | 取消原因；取 `cancel` 的 `reason`（003 起必填） |
| `defer_reason` | string \| null | 暂缓原因；非空即“已暂缓”；`claim`/`undefer`/终态清空 |
| `deferred_at` | ISO \| null | 最近一次暂缓时间；`defer` 写入 |
| `deferred_until` | ISO \| null | 计划恢复时间；`defer` 的 `deferred_until`（可选） |
| `risk_note` | string \| null | 隐患说明；非空即“曾/正带隐患”；`flag_risk` 写入，解除与终态不清空 |
| `risk_flagged_at` | ISO \| null | 最近一次标记隐患时间；`flag_risk` 写入 |
| `risk_resolved_at` | ISO \| null | 隐患解除时间；`null` 表示仍未解除；`unflag_risk` 写入 |
| `risk_resolution` | string \| null | 解除时的复盘结论；`unflag_risk` 的可选 `reason`；重新标记时清空 |

`unblock` 不清空 `blocked_at`/`blocked_reason`，它们保留“最近一次被阻塞”的历史，便于界面计算阻塞时长。

`TaskView` 另带 `unread_count`（number）：该任务下 `status <> 'archived'` 且没有 `card_read` 记录的卡数。`GET /api/tasks`、`GET /api/tasks/tree`、`GET /api/tasks/{id}` 与 MCP `task.list` / `task.tree` 口径相同；任务树用它渲染未读红点。

**结束通知字段**：`end_notice_read_at`（ISO \| null）是用户确认“我看到这个任务结束了”的时间；`end_notice_pending`（boolean）由服务端派生，等于“任务处于 `done` / `failed` / `cancelled` 且 `end_notice_read_at IS NULL`”。任务每次进入终态都会清空 `end_notice_read_at`，Web 任务树据此给整行加高亮和圆点。用户点击任务行时调用 `POST /api/tasks/{id}/ack-end-notice` 写入已读，接口返回最新 `TaskView`；对未结束任务调用返回 `CONFLICT`（`TASK_NOT_ENDED`），重复确认幂等并保留首次已读时间，且**不更新** `updated_at`（查看回执不是任务内容变化）。该动作是 Web/REST 交互，不属于 MCP 工具清单。

### 4.8 任务（MCP-009~016）

**执行方登记顺序**：

```text
task.create（draft）
  → task.update(event="submit")（pending）
  → task.claim（claimed，返回 claim_token）
  → task.update(event="start")（in_progress）
  → 干活；需要暂停用 block
  → 先发 status/artifact 证据卡
  → task.update(event="complete")
```

**建议任务的登记路径**（`kind="suggestion"`）：

```text
task.create(kind="suggestion")   # 不 submit，停在 draft（挂起，等用户批准）
  → 用户在任务树点“提交待认领”，或口头同意
  → task.update(event="submit")（pending）
  → task.claim → task.update(event="start")
```

建议**不进 `blocked`**：`blocked → unblock` 必须携带 `claim_token`，而令牌只存在于认领方会话、活不过会话，用户在网页上也无法把 `blocked` 任务重新认领。`draft` 是唯一“用户可一键推进”的挂起位。

禁止“只发卡不登记任务”。所有任务查询与状态事件返回 `TaskView`，含 §3.3 的状态时间线字段。

| `task_id` | 必填 |
| `event` | 状态事件：`submit`/`start`/`block`/`unblock`/`complete`/`fail`/`cancel`/`release`；暂缓事件：`defer`/`undefer`（不改变 `status`）；隐患事件：`flag_risk`/`unflag_risk`（不改变 `status`，任何状态可用） |
| `claim_token` | 状态事件必填（除 `submit`/`cancel`/`defer`/`undefer`/`flag_risk`/`unflag_risk`） |
| `patch` | 非状态字段：`title`/`description_md`/`priority`/`assignee`/`tags`/`category`/`due_at` |
| `reason` | `fail`/`block`/`cancel`/`defer`/`flag_risk` 必填（标记隐患时要写清“留了什么坑”）；`unflag_risk` 可选，作为复盘结论 |
| `deferred_until` | `defer` 可选：计划恢复时间（ISO 8601） |
| `evidence_card_ids` | `complete` 可选；不传则由服务端自动查关联卡 |

> `event` 与 `patch` 可在一次调用中同时给出；服务端按“先校验状态、再应用 patch”的顺序在同一事务内完成。

**时间线写入点**：`claim`（含过期租约接管）写 `claimed_at` 并清空暂缓三列，续租不改写；`start` 写 `started_at`；`block` 写 `blocked_at` + `blocked_reason`；`unblock` 不清空 `blocked_at`/`blocked_reason`；`complete` 写 `completed_at`；`fail` 写 `failed_at` + `fail_reason`；`cancel` 写 `cancelled_at` + `cancel_reason`；`defer` 写 `defer_reason` + `deferred_at` + 可选 `deferred_until`（仅 `draft`/`pending`）；`undefer` 清空暂缓三列，未暂缓时报 `CONFLICT TASK_NOT_DEFERRED`。所有终态事件都会清空暂缓三列。`flag_risk` 写 `risk_note` + `risk_flagged_at`，并清空 `risk_resolved_at`/`risk_resolution`；`unflag_risk` 写 `risk_resolved_at` + 可选 `risk_resolution`，保留原文；两者都不随认领或终态清空。

**`task.list`**：`{channel_key?, status?, assignee?, tags?, parent_id?, has_risk?, risk_open?, include_closed?=false, include_description?=false, page?, page_size?}`。`has_risk=true` 含已解除，`risk_open=true` 只看未解除。
**`task.tree`**：`{channel_key, depth?=2, root_id?, include_closed?=false, include_description?=false}` → 嵌套节点（默认 2 层），节点含状态时间线字段。

> **默认过滤（仅 MCP 查询入口）**：`task.list` / `task.tree` 默认省略 `done` 与 `cancelled`，`failed` 仍返回；显式 `status=done|cancelled`（仅 `task.list`）或 `include_closed=true` 可查历史。**例外（仅 `task.list`）**：传 `has_risk=true` 或 `risk_open=true` 且未显式传 `status` 时自动包含终态，保证“复盘带隐患完成的任务”不会漏掉已结束记录；显式 `status` 仍优先。`task.tree` 过滤时把已结束节点的未结束子代提升一级，避免整棵子树消失。REST 接口保持返回全量，不受该默认值影响。

> **默认省略描述（MCP 与 REST 一致）**：`task.list` / `task.tree` 默认不返回 `description_md`，避免 base64 截图灌满上下文；需要正文时传 `include_description=true`。任务详情与写操作回执不受影响。省略发生在 SQL 投影层：默认查询用显式列清单把该列投影为 `NULL`，不会先把 TEXT 读进 Node 内存再丢弃。无事件更新写 `task_event.detail_json` 时，描述只记 `[omitted N chars]`，不复制全文。
**`task.claim`**：`{task_id, harness_id, lease_seconds?=900, claim_token?}` → `{task, claim_token}`；`task` 含 `claimed_at` 等时间线字段。

续租复用同一个工具：已持有该任务时带原 `claim_token` 再调一次，服务端延长租约并返回同一 token，不产生新事件。`claim_token` 不匹配或租约已过期 → `ALREADY_CLAIMED`，调用方必须停止执行并重新排队。
**`task.release`**：`{task_id, claim_token, reason}` → `{task}`。
**`task.move`**：`{task_id, new_parent_id}` → `{task}`。
**`task.copy`**：`{task_id, new_parent_id?}` → `{tasks[]}`。新节点一律为 `draft`，时间线与认领/暂缓/隐患四列全部重置——复制的是任务结构，不是某一次交付的历史。

### 4.10 摘要（MCP-019）

### 4.11 主通道记忆（MCP-020~023）

“主通道”= `channel_key` 的 project 段（AGENTS §3.4）：同一项目的多个话题通道共用一份记忆。整篇 Markdown 是唯一真相，按 `project` 存取；用户在 Web 上整体编辑，agent 通过下面四个工具追加与检索。

**MCP-020 `memory.get`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project` | string(≤200，单行) | 是 | 主通道名，即 `channel_key` 第二段 |

返回 `ProjectMemoryView`：`{project, content_md, version, exists, line_count, updated_by, created_at, updated_at}`。
没有记忆时返回 `exists=false`、`version=0`、`content_md=''`，**不是** `NOT_FOUND`——空记忆是正常初始状态，agent 不需要先判断“要不要创建”。

**MCP-021 `memory.append`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project` | string | 是 | 同上 |
| `lines` | string[]（1~50 行，单行 ≤2000 字符） | 是 | 一行一条长期约束 |
| `dedupe` | boolean，默认 `true` | 否 | 按行 trim 后去重；已存在的行不会重复追加 |

返回 `{project, version, appended, skipped_duplicates, skipped_blank, line_count, updated_at, unchanged}`。
`unchanged=true` 表示这次没有任何新行（全是重复/空行），调用方不必再发通知。

**为什么追加放在事务里**：去重依赖当前全文；先读后写会让并发追加的后一次覆盖前一次。服务层用 `BEGIN IMMEDIATE` 包住读-改-写，并用 `WHERE version = ?` 兜底。

**MCP-022 `memory.search`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project` | string | 是 | 同上 |
| `query` | string(≤200) | 是 | 大小写不敏感的子串，对应约定的 `[key]` |
| `limit` | number，默认 50，最大 100 | 否 | 最多返回几行 |

返回 `{project, query, version, total, truncated, matches:[{line_no, line}]}`。
`line_no` 是 1 基行号；命中行超过 2000 字符时截断并加 `…`。**只回命中行、不回全文**，让 agent 在上下文有限时先搜再决定是否 `memory.get`。

**MCP-023 `memory.update`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project` | string | 是 | 同上 |
| `content_md` | string（≤64,000 字符） | 是 | 新全文 |
| `expected_version` | integer ≥0 | 是 | 先 `memory.get` 拿到的版本；0 表示“我认为还不存在” |

返回 `{project, version, changed, line_count, updated_at}`，**不回传正文**（调用方刚提交过，回传只会重复占用上下文）。

**版本冲突**：`expected_version` 与服务端不一致时返回 `CONFLICT / MEMORY_VERSION_CONFLICT`，`details.actual_version` 给最新版本。调用方应重新 `memory.get`、合并后再保存；不要盲目重试。内容与当前完全相同时返回 `changed=false` 且不递增版本。

**写入口的共同约束**：

- 追加与整体编辑都做敏感模式扫描，命中返回 `INVALID_ARGUMENT / SENSITIVE_PATTERN_DETECTED`（只给模式名，不回显原文）；
- 追加后总长超过 64,000 字符返回 `MEMORY_TOO_LARGE`——记忆是长期约束，不是日志，需先整理；
- 写入成功落审计 `memory.append` / `memory.update`，`object_type='project_memory'`。

## 7. 值守壳配置与 CLI

### 7.0 传输方式

值守壳**只作为 MCP 客户端**，不另开一套 REST 客户端，也不为它增加 REST 端点。理由：它需要的 6 个动作（注册、心跳、列任务、认领/续租、回报、释放）在 MCP-001/002/011/013/010/014 里已经齐全；再维护一套 REST 调用只会让同一语义有两份实现。

| 值守壳动作 | 使用的 MCP 工具 |
|---|---|
| 注册 / 心跳 | `harness.register`、`harness.heartbeat` |
| 扫可认领任务 | `task.list` |
| 认领 / 续租 | `task.claim`（带 `claim_token` 即续租） |
| 回报完成/失败 | `card.post` + `task.update` |
| 主动放弃 | `task.release` |

`aidash_url` 可写服务根地址（如 `http://127.0.0.1:8787`），也可写完整 `/mcp`；客户端会归一化
（补 `/mcp`、去掉 query/hash、拒绝 URL 内嵌账号密码）。REST 只服务浏览器端 Web。

### 7.1 配置文件

默认 `aidash-watch.json`（当前工作目录），可用 `--config` 指定。

```json
{
  "aidash_url": "http://127.0.0.1:8787",
  "harness_id": "watchdog-a",
  "name": "值守壳 A",
  "host": "devhost",
  "capabilities": ["dev"],
  "channels": ["devhost/*"],
  "poll_interval_seconds": 60,
  "gap_seconds": 10,
  "lease_seconds": 900,
  "heartbeat_interval_seconds": 30,
  "command_timeout_seconds": 1800,
  "concurrency": 1,
  "commands": [
    {
      "command": "pnpm -C 40-build test",
      "tags": ["test"],
      "title_prefix": "[自动]",
      "channel_key": "devhost/myproj/*",
      "timeout_seconds": 600,
      "cwd": ".",
      "env": { "CI": "1" }
    }
  ]
}
```

**规则**：

- 令牌没有配置项，只从环境变量 `AIDASH_TOKEN` 读；`token_env` 等旧字段会被告警并忽略。
- 每条 `commands[]` 规则必须至少有一个选择器（`tags`/`title_prefix`/`channel_key`）或显式
  `match_all: true`，否则拒绝启动——防止“少写一个字段就把所有任务都跑了”。
- `tags` 是 AND 匹配；`title_prefix` 大小写不敏感；`channels` 为空表示不限制。
- 相对 `cwd` 按配置文件所在目录解析；`env` 里的敏感键（`AIDASH_TOKEN`/`AIDASH_LLM_API_KEY`）被拒。
- 没有配置文件时**只允许 `status`**；`run`/`once`/`dry-run` 直接报配置错误，不会认领任务。
- `AIDASH_URL`/`AIDASH_TOKEN` 环境变量优先于配置；`concurrency` 目前只支持 1。

### 7.2 CLI 命令

| 命令 | 作用 | 退出码 |
|---|---|---|
| `aidash-watch run` | 常驻：注册、心跳、轮询、认领、执行、回报 | 见下 |
| `aidash-watch once` | 只跑一轮（最多 1 个任务） | 见下 |
| `aidash-watch status` | 只读：打印 digest 摘要与任务统计，不写库、不注册 | 0 |
| `aidash-watch dry-run` | 只读：列出将认领的任务与命令，不执行 | 0 |
| `aidash-watch --version` / `--help` | 版本/帮助 | 0 |

退出码：`0` 正常（含 Ctrl+C 优雅停止）；`1` 业务错误（服务端拒绝、证据缺失、回报失败）；
`2` 配置/认证/传输错误（令牌缺失、401、配置非法、连不上 MCP）。

### 7.3 子进程约定

- 命令经 shell 启动：Windows `cmd /d /s /c`，POSIX `sh -c`。命令来自**本机配置文件**，
  不把任务标题/正文拼进命令行（它们只作为 `AIDASH_TASK_*` 环境变量传入），因此不引入远程注入面。
- stdout/stderr 各截断到 16KB；状态卡的 `summary`/`detail_md` 在落库前脱敏。
- 退出码非 0、启动失败、超时都算失败；超时/中断会杀整个进程树（Windows `taskkill /T /F`）。
- 任务按 `claim → start → status 卡 → complete/fail` 顺序回报；只有“确认无法处理”才 `release`。
- 命令是**至少一次**语义：进程在“命令已执行、回报未送达”窗口崩溃时，重跑会再次执行命令。
  因此 `commands[]` 应写幂等命令（测试、构建、只读检查），不要放不可重复的副作用操作。
