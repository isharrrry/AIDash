## 0 本轮做到哪一步

4B 的输入是“实测结果”，不是“设计愿望”。本轮已经有真实进程与浏览器实测，
因此可以对已完成项下“可确认”，但**未实测项一律写 `需实测`，不写“应该没问题”**。

**本轮新增 4 项实测（2026-10-25）**：备份恢复演练、SEA 单文件打包、许可证原文核对、SBOM 生成。

**剩余 2 项不具备实测条件**：#10 跨主机 TLS 需要一台目标服务器（当前单机自用场景不适用）、
v1 数据迁移需要旧数据样本（本机没有）。两条都写明了理由，不冒充“通过”。

> **顺带纠正 4A 的一处计数错误**：§7 表格实际只有 11 条（编号 1~8、10~12，#9 缺号），
> 但自检写的是「12 项」。缺号项对应 v1 数据迁移，现只在 C-12 出现。详见 `技术规格清单.md` §7.3。

## 2 结论分类规则（三类，不许有第四类）

| 类别 | 判定条件 | 需要的证据 |
|---|---|---|
| **可确认** | 有实测输出或官方文档直接支持，且版本已锁定 | 命令 + 输出 + 日期，或官方文档链接/章节 |
| **需实测** | 目前只有推断，或实测环境与目标环境不一致 | 写清缺什么、怎么测 |
| **不建议** | 实测失败，或存在无法接受的许可证/兼容风险 | 失败输出；并给出处置：改技术选型（记 ADR）或改设计约束（记 COR） |

**禁止表述**：“基本可行”“大致支持”“应该没问题”。出现即视为本轮不合格。

## 附录 A：ADR-016（2026-10-25 已裁决：接受，目录分发）

> 按 `设计文档包/01` §5.2「改一条 ADR 在末尾加修订段，不覆盖原文」与指南铁律五，
> 本 ADR 已追加到 `概要设计.md`；`model.json` 的 `adrs` 计数与 `ADR` 编号范围同步改为 16。

### ADR-016：不采用 Node SEA 单文件打包，改为目录分发

- **原结论**：ADR-009 的后果写明「跨平台分发用 Node 单文件打包」。
- **新结论**：放弃单文件打包；值守壳以 `node aidash-watch.mjs` 运行，服务端与 Web 以目录形式分发。
- **背景（实测，2026-10-25）**：
  1. 值守壳现有产物是 ESM（`aidash-watch.mjs`，746 KB）。注入 SEA 后运行报
     `SyntaxError: Cannot use import statement outside a module` —— SEA 的入口执行器 `embedderRunCjs` 只认 CommonJS。
  2. 改打 CJS 时 esbuild 直接失败：`src/cli/index.ts:283` 的 `await main(...)` 触发
     `Top-level await is currently not supported with the "cjs" output format`。
     即：**ESM 进不去，CJS 打不出来**，两条路都断。
  3. 服务端另有独立阻断：`better-sqlite3` 是 native 模块，不能进 blob，运行报 `ERR_UNKNOWN_BUILTIN_MODULE`。
- **理由**：SEA 的 blob 只能装 JS；而本项目的两个入口分别卡在 ESM/top-level await 与 native 模块上，都不是配置问题。
- **影响**：
  1. 部署物从「一个 exe」变成「一个目录 + 一份 node 运行时」；
  2. 升级是替换目录，不是替换文件；
  3. 对外不能再说「单文件分发」；
  4. 若将来必须单文件，只能换掉 `better-sqlite3`（例如 `node:sqlite`），但那会丢掉 Backup API——而备份方案已由 C-10 实测确认可用，换驱动等于放弃已验证的能力。
- **替代方案**：
  - `pkg`：已停止维护，同样不能打 native 模块；
  - 把 JS 内联、`.node` 放外部目录：那已经不叫单文件，不如直接目录分发。
