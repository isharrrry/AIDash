## 3. 演示数据怎么造

所有通道、任务、卡片都使用合成内容，没有真实人名、真实项目路径或真实凭据。

### 3.1 演示通道

通过 `POST /api/channels` 创建：

```json
{
  "channel_key": "demo-host/alpha-demo/release-gate",
  "title": "演示：Alpha 发布前收口",
  "alias": "演示 Alpha 发布前收口",
  "workdir": "F:/demo/alpha"
}
```

`workdir` 是明显的演示路径；通道 key 也是合成值。

### 3.2 演示 harness

任务认领要求 harness 已注册。通过临时实例的 MCP 工具注册：

```text
harness.register({
  harness_id: "demo-alpha-agent",
  name: "演示 Alpha 助手",
  capabilities: ["demo", "readme-screenshot"]
})
```

截图中看到的 `demo-alpha-agent` 是合成 harness ID。

### 3.3 三条任务（父子层级）

通过 `POST /api/tasks` 先建父任务，再带 `parent_id` 建两条子任务。`submit: true` 后任务进入待认领；再通过 `POST /api/tasks/{id}/claim` 和 `PATCH /api/tasks/{id}` 的 `start` 事件推进状态。

| 任务 | 层级 | 截图时状态 |
|---|---|---|
| 演示：Alpha 发布前收口 | 父任务 | 进行中 |
| 演示：核对 Beta 回滚清单 | 子任务 | 进行中 |
| 演示：补齐白名单证据 | 子任务 | 待认领 |

任务分类、负责人（如“演示-Alpha执行”）和标签均为演示用合成值。

### 3.4 决策卡与信息卡

通过 `POST /api/cards` 创建两条 question 卡和一条 info 卡：

1. `演示：先回滚还是先修白名单？`（P0，挂在父任务下）
   - 四段必填：议题背景、达到目的或结果、调查参考、决策项描述
   - “立即回滚”为 `primary` 主推荐
   - “等白名单修复”为 `backup` 备选推荐
   - 两项都提供优点和缺点
2. `演示：Beta 验收先灰度还是直接全量？`（P1，挂在第一条子任务下）
   - “先灰度 5%”为主推荐，“直接全量”为备选推荐
   - 同样是完整四段背景和优缺点
3. `演示：发布前检查已完成`（info，挂在父任务下）
   - 用于让任务树出现未读信息标记

question 卡若缺四段、缺任一项 `pros_md`/`cons_md`，或没有恰好一个主推荐加一个备选推荐，会被服务端拒绝。

## 4. 浏览器与隐私处理

- 本机没有安装 Google Chrome，Chrome DevTools MCP 不可用。
- 改用无头 Edge 155 + 隔离的临时用户目录 + CDP（调试端口 9333）导航和截图；没有使用日常 Edge 资料。
- 登录方式：在页面 origin 下写入 `localStorage['aidash.token'] = demo-token-readme-2026`，并写入 `sessionStorage['aidash.channel']` 选中演示通道，然后刷新页面。
- 截图使用 CDP `Page.captureScreenshot`，`captureBeyondViewport: false`，没有使用整页截图。
- `03-settings.png` 使用 1920×1200 视口，截图前执行 `document.body.style.zoom = '0.75'`。另临时注入 `.settings-group dl > p { grid-column: 1 / -1; }`，让说明段落跨两列，避免“已配置”和保留天数被挤成逐字换行；该样式只作用于截图页，源码未改。
- `03-settings.png` 中，含本机用户名与绝对路径的 3 处数据库/秘密路径叶子文本在截图前做了 CSS 模糊处理；除此之外未改文字或数据，唯一额外布局调整是上一条的跨列规则。这样做是为了避免把本机用户名带进公开仓库，同时保留健康检查与“已配置”状态的可见性。
- 四张图中没有真实令牌、真实人名或真实项目路径。

- 截图页面的文本快照中未出现 8787，也未出现假 token 明文；这些文本快照仅保存在临时目录，已随清理删除。

## 6. 已知取舍与遗留问题

- Chrome DevTools MCP 不可用，本次按允许的替代方案改用 Edge CDP；截图真实性不受影响。
- `03-settings.png` 的换行根因是 `.settings-group` 把说明段落也放进两列 `<dl>`，占用了第一列。为满足本轮“值单行可读”的要求，截图时临时注入 `.settings-group dl > p { grid-column: 1 / -1; }`，并设置页面 zoom 0.75；源码未改。若希望产品本身也这样显示，需要单独修前端 CSS。
- 0.75 缩放下页面内容在 1920 宽视口内约 1080 px 宽，两侧留白较多；这是本轮缩放要求的视觉结果。
- 健康检查中的临时数据库路径为隐私做了模糊处理，因此不能从图片直接读出完整路径；路径验证见 `/healthz` 和临时环境配置。
- `04-card-drawer.png` 的文件名沿用任务约定，但实际界面是 question 卡专用的较大模态框；普通卡片才使用右侧抽屉。
